# VerdFlow 资源中心设计与实施评估

日期：2026-10-22。

状态：总体方案已接受，独立资源仓库与首批 Release 附件已建立。
首批资源为 DTS_Library_v6 与三个种植策略；2026-10-23 追加“花坛点景”和“草坪铺设”两个种植方案。
PAK 始终仅记录外部下载入口。
本轮采用 Resources 独立托管页面，并在浏览器中按需加载资源说明。
具体实现范围与上线条件见 resource-format.md、release-checklist.md 和 ADR-0001。

## 1. 目标与范围

在 Resources 仓库中建设独立的资源中心，统一发现、下载和更新 VFA、VFS、VFP。
作者通过 Issue 或 PR 投稿，由维护者审核、发布。初期使用静态页面和 GitHub 托管，
不需要常驻服务器、数据库或额外账号系统。

资源中心使用 GitHub Pages 项目站点；官网 verdflow-site 提供导航入口和手册链接。
“静态托管”不限制浏览器使用 JavaScript 请求 JSON 和 Markdown，也不意味着可以省略资源发布步骤。

PAK 全部为外部链接。本仓库只分发三类 VerdFlow 交换包，并维护它们的索引、说明和展示素材。
客户端内一键安装、自动资源升级、评分、评论、作者后台和交易不属于本期范围。

## 2. 模块归属

| 模块 | 拥有的内容 | 日常变更 |
| --- | --- | --- |
| Resources / web | 通用资源列表、搜索筛选、详情模板、Markdown 展示、版本选择、导航和加载状态 | 调整资源中心的页面、交互和展示字段 |
| Resources / entries | 资源索引输入、版本记录、作者、许可、README、图片、包下载、配套 PAK 外链 | 上架资源、更新版本、修正介绍和链接、撤回版本 |
| Resources / scripts 与工作流 | 内容校验、索引生成、资源附件与 Pages 发布 | 维护资源发布流程 |
| Site | 官网、使用手册、资源中心入口 | 更新产品文档和官网设计 |
| 客户端 / SystemHost | 本地资源库、导入、兼容解析、信任、任务与快照 | 继续按产品既有边界演进 |
| DTS Adapter / Provider | 平台资产的解析、检查和使用 | 平台资源就绪性，不由站点代为判断 |

资源内容只维护一份，以 Resources 的条目记录与 README 为准。网页消费的索引和内容快照为派生产物。
同一仓库内仍保持页面、数据和发布工具分层；资源更新不写入页面组件，不调用产品 Core。
资源中心复用已有品牌素材和视觉规范，首期无需抽取跨仓库运行时组件库。

对比上一版方案：

| 方案 | 更新范围 | 适用情况 |
| --- | --- | --- |
| Site 在构建时读取 Resources | 内容发布后还要刷新 Site；需要协调两份构建 | 希望所有内容都纳入同一文档站 |
| Site 在浏览器中动态读取 Resources | 内容更新无需重建 Site；页面与数据仍跨仓库维护 | 希望资源中心与官网共用页面框架 |
| Resources 同时持有独立页面和内容 | 资源与页面在同仓库发布，Site 只维护入口 | 当前推荐，资源可独立维护和扩展 |

动态加载不要求页面一定放在 Resources。独立托管的主要收益是职责集中和发布独立，
代价是维护另一套页面入口、部署流程与品牌样式；仍应保留页面与内容之间的稳定数据接口。

Pages 的项目站点默认位于 `https://<owner>.github.io/<repository>/`，不要求新建
第二个 `<owner>.github.io` 用户站点。实际地址在远端仓库确定后配置。

## 3. 页面设计

现有 Site 的 `/resources/` 继续作为使用手册。官网导航的“资源中心”链接至独立的 Resources Pages。
资源中心页头保留品牌、返回官网和用户手册入口，使两个站点之间可以直接往返。

### 列表

- 沿用站点的浅色背景、绿色主色、字体和图标风格，直接呈现可浏览资源。
- 顶部三类切页：资产、策略、种植方案；默认进入资产页签，支持带类型的直接链接。
- 搜索匹配名称、简介和作者；仅在已有数据足以支撑时增加平台等筛选。
- 桌面三列卡片，窄屏两列，手机一列。列表状态保留在 URL，返回时恢复类型和搜索条件。
- 每张卡片展示一张清晰预览图、名称、简述、作者与当前推荐版本；点击进入详情。
- 资产图优先展示库中代表植被，策略图展示作者提供的构图示意，方案图展示实际或明确标注的示例效果。
- 没有资源时如实显示空状态；不造样例包，不提供无效下载按钮。

### 详情

| 类型 | 主要内容 | 下载与关联 |
| --- | --- | --- |
| 资产库 | 代表植被、数量与分类、适用平台、库版本、安装说明 | 下载 VFA；独立的“获取配套 PAK”外链，可有多个配套包 |
| 策略 | 用途、角色与效果示例、适用范围、已验证产品版本 | 下载 VFS；使用指南；历史版本与更新说明 |
| 种植方案 | 效果图、所用植被、参数摘要、适用平台 | 下载 VFP；需要的策略；关联来源资产库；使用所需的外部平台资源 |

详情默认展示明确指定的推荐版本，历史版本可以独立访问和下载。
页面同时提供介绍、使用说明、版本记录和作者信息；首期不增加评分、下载排行榜或评论区。
版本、体积与校验值来自发布记录；不存在的信息不编造为统计数据。

每个资源仍有可分享的稳定详情地址，但由一个通用详情组件渲染，无需为每项资源编写 Vue 页面。
GitHub Pages 的详情入口需支持直接打开和刷新；首期可使用固定详情 HTML 加查询参数，
不依赖服务器不存在的任意路径重写。页面更新标题，并保留资源、版本和当前筛选条件。

## 4. 关联语义

三种关系必须分别表达，不统一标成“必须安装”：

1. 所需策略：从 VFP 提取真实策略身份与保存版本，链接对应资源及版本记录。
   兼容解释遵循现有产品语义版本规则，网页不替代本地安装、信任和结构校验。
2. 来源资产库：帮助用户追溯植被来源，允许一个方案关联多个库。VFP 已携带资产快照，
   不能把这些链接转成新的强制安装条件。没有可公开的来源时按缺失来源处理。
3. 外部平台资源：VFA 或 VFP 中引用的 DTS 模型仍须在目标平台可用。
   PAK 链接、配套版本与安装说明放在资源记录中；是否已安装由目标平台链路检查。

公开条目身份与包内 strategy_id / catalog_id / profile_id 分开保存，并建立明确映射。
作者归属冲突必须在收录时解决，不通过改写他人包内 ID 来临时避开。
页面使用名称展示资源，内部 ID 用于稳定引用。

## 5. 数据组织

以下为当前组织结构，具体字段见 schemas/resource.schema.json；该 schema 仅约束网站记录。

```text
web/
entries/
  assets/<entry-id>/
    resource.json
    README.md
    media/
  strategies/<entry-id>/...
  plans/<entry-id>/...
docs/
scripts/
.github/
  ISSUE_TEMPLATE/
  workflows/
```

每个资源由一份结构化记录、一份 README 和展示素材构成。README 描述用途、效果、
操作和注意事项；resource.json 保存程序需要读取的身份、类型、版本、依赖、许可和附件信息。
自动生成供资源中心消费的总索引，避免人工同步单条记录和总表，也不从自由文本反推版本与依赖。
Git 保存记录、README 和轻量展示图；VFA/VFS/VFP 上传到 Releases，包文件不进入 Git 历史。

README 属于分发条目的介绍，不要求改变 VFA/VFS/VFP 格式或向包内重复添加同一份文档。
纯说明修订无需重新导出交换包。查看历史资源版本时，使用该版本对应的说明快照，
避免下载旧包却显示只适用于新版本的用法。

| 信息 | 来源 |
| --- | --- |
| 条目身份、分类、作者、简介、封面、许可 | 结构化记录，由发布者维护并审核 |
| 详细介绍、效果图与操作说明 | 每项资源自己的 README 与 media |
| 包内身份、策略版本、候选资产及参数摘要 | 能从包静态解析的字段优先自动提取 |
| 版本说明、已验证环境、推荐版本 | 发布者维护 |
| 下载 URL、文件大小、SHA-256 | 发布工具核对实际附件后生成 |
| 所需策略、来源资产库、配套 PAK | 包内事实加维护者确认的公开条目与外链映射 |

发布版本与 schema 版本分开：VFA/VFP 的格式版本不能当作资源发布版本；
VFS 的发布版本应与其策略声明保持一致。兼容不能仅凭上传时间或名字推断。
归档文件 SHA-256 与产品中的策略内容身份 hash 分开记录，不相互冒充。
下载指向明确版本；旧版本文件不覆盖。撤回记录保留说明，取消推荐与下载入口。

## 6. 动态加载与发布

浏览器加载逻辑：

1. 加载通用页面与轻量总索引，展示分类、卡片和搜索结果，不下载全部 README 或资源包。
2. 点击某项资源后，按索引指向的版本读取详细记录和 README，加载详情图片。
3. 使用统一的 Markdown 渲染器展示正文，版本和下载按钮由结构化记录生成。
4. 用户选择下载时才获取 Release 附件；获取 PAK 时打开提供方入口。

JSON、README 和展示素材由 Resources 自己的 Pages 提供，按需请求；不要求访客调用 GitHub
仓库 API 或直接读取可变 main 分支上的 raw 文件。资源包继续使用 Releases 下载链接。
页面包含加载、请求失败与重试状态；索引与正文通过同一内容版本关联，避免缓存混用。
可变的推荐版本索引需要重新验证；带版本的说明与图片可以缓存，旧说明引用保持有效。

README 支持普通 Markdown、表格、图片和链接；相对图片路径按对应资源目录解析。
不运行 Vue、脚本或包内代码；作者不能通过 README 改写页面结构与下载按钮。
渲染器限制原始 HTML 与链接协议，避免社区内容被当作可执行网页。

日常发布流程：

1. 从现有 Author / Studio 导出包，在本地 `.work/` 或 `.downloads/` 准备待发布文件。
2. 投稿或修改资源记录，核对包内身份、格式、许可、关联、图片及 PAK 链接。
3. 审核后上传三类包到固定版本 Release，并核对文件大小与 SHA-256。
4. 只有附件就绪后，才把已发布版本加入正式索引并选择推荐版本。
5. Resources 自己的工作流生成轻量索引及可按需获取的内容快照，记录确定的源 commit。
6. 校验关联、下载声明、README、链接和页面后，将通用前端与静态数据一起部署到 Resources Pages。

推荐以“发布附件就绪且索引合入”为上线触发点。内容变更不需要修改页面组件，
也不要求触发 Site 构建或配置跨仓库通知。初期沿用一次完整 Pages 部署保证发布一致性；
前端代码未变化时无需人工重做页面，但不能承诺单纯提交 README 就绕过部署立即在线更新。
保留手动部署入口；校验或构建失败则停止部署并保留上一版线上页面。

纯浏览器动态正文对搜索收录和链接分享摘要存在取舍：能够执行 JavaScript 的搜索引擎
可能读取正文，但并非所有爬虫或分享工具都能执行。初期以目录访问和下载为主要目标；
若后续需要每项资源独立的搜索落地页或分享图，可从同一份元数据和 README 自动生成
静态摘要或预渲染页面。它们是派生产物，不增加手工维护的第二份详情文档。

外部 PAK 可能受登录、有效期或下载方式影响，记录可访问的提供方入口和使用说明，
不能把简单 HEAD 请求通过当作完整安装可用性保证。

## 7. 投稿与维护

- Issue 表单面向不熟悉 Git 的作者，收集介绍、截图、包链接、作者和许可；由维护者整理入库。
- PR 面向熟悉 Git 的作者，修改资源条目与文档，自动进行静态检查。
- 审核与发布由维护者完成。下载、收录或作者身份不自动授予本地执行信任。
- 首期自动校验包结构、记录、哈希和关联；运行策略进行验证时继续使用独立隔离环境。
- 问题版本可以撤回，外部下载链接失效可以更新入口，旧制品身份不因改链接而变化。

## 8. 实施与验收

| 工作 | 粗估人日 | 结果 |
| --- | --- | --- |
| 数据记录、静态校验、投稿模板 | 1-2 | 一份可维护的数据源与收录流程 |
| Resources 通用列表、动态详情与版本关联 | 2-3 | 三类资源统一展示，README 按需加载，桌面和手机可用 |
| Release 附件与 Resources Pages 发布 | 1-2 | 数据更新后独立发布，不需要刷新官网 |
| 端到端核验与维护说明 | 1-2 | 版本、链接、构建输入与线上结果一致 |

合计约 5-9 人日，为初期粗估；不含真实资源整理、正式包审查、额外截图制作、
客户端内安装管理、搜索预渲染与第三方策略执行沙箱。现有品牌和 GitHub 托管可复用，
此范围内不需要新增常驻服务器或数据库。服务配额及真实访问情况在上线时复核。

验收关注用户可见行为：

- 同一资源发布新版本时列表更新、旧版本仍可定位；没有新客户端版本也可正常分发。
- 方案能导航到所需策略和多个来源库，资源名称清晰，来源库缺失不会被写成新的执行门禁。
- PAK 始终是外部入口；下载策略包不触发策略执行或自动信任。
- 未完成的发布不展示为可下载；撤回版本不再作为推荐。
- Resources 使用确定索引版本，更新失败保留线上旧版；手动入口可以恢复发布。
- 修改资源内容不需要修改页面组件或重新发布 Site；新增资源由索引自动展示。
- README 按需读取，历史说明匹配所选版本；相对图片、缓存更新、错误重试可用。
- 项目子路径、直接打开和刷新详情地址、键盘、窄屏与空状态可用。
